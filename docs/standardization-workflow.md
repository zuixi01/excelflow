# 商品标准化工作流

## 当前范围

新任务通过工作台选择已发布的业务模板，上传供应商 Excel；同一任务统一使用所选模板的字段快照。左侧“模板管理”维护各业务模板，原字段配置保留为“通用商品模板”。旧 SOP 后端、历史任务的维护回传与输出模板兼容，以及历史核对工具保留。

1. 在左侧“模板管理”新建、复制或编辑业务模板，维护固定字段和动态字段，保存草稿并发布。
2. 在新任务中选择模板，再上传一个或多个供应商 Excel 文件，合并为一个任务，识别有效工作表、多层表头和合并数据行。
3. 固定字段与全部启用的动态字段自动组成统一目标结构，对每个供应商工作表一起匹配；运营只确认映射，不选择动态类目。配置了模型时自动给出语义建议；未配置或请求失败时明确提示，并列出未匹配字段。
4. 将匹配列填入标准字段，未匹配的原表列作为任务内的“原表保留列”追加在全部动态字段之后，支持在线维护、补录、下载维护表与回传。
5. 按任务字段快照生成 `标准商品表.xlsx`，无需另选输出模板。

外部运营平台接口尚未接入。动态字段默认为空；配置页的本地字段组、商品属性和商品规格作为模拟接口字段，不代表真实平台规则。字段组名称仅用于组织、区分字段，不按供应商工作表名称开启或关闭字段。最终输出为一个 `标准商品` 工作表，按固定字段 → 商品属性 → 商品规格 → 原表保留列排列；动态字段在最终表中汇总成两列，维护表仍逐字段分列。

## 最终表的动态字段展示

- 仅在生成标准化最终表时，将已配置的动态字段按“商品属性”“商品规格”分别合成一列。每条商品按任务快照中的字段顺序写成 `品牌：三雄极光、系列：、名称：防眩筒灯`、`款式：PAM、功率：3W`；空值保留字段名与冒号，使用中文顿号分隔。
- 使用运营在线维护或回传并确认保存后的当前值；固定字段的值和类型、原表保留列、维护表列结构及回传规则保持原样。同一栏目内不同字段组的重名字段用 `字段组·字段名：值` 区分。
- 汇总列每条商品独立显示，不纵向合并，即使来源字段包含合并单元格。文本自动换行并调整行高；拼接后超过 Excel 单元格 32,767 字符上限时明确报错，不截断数据。
- 新旧标准化任务在再次点击“生成最终表”时采用此格式；已经生成的历史文件不覆盖。导出批次单独保存汇总方案和数据快照，页面预览、Excel 下载与 ZIP 中的 Excel 使用同一份产物。未配置某一类动态字段时，不添加该类空栏目。

## Excel 维护表的自由结构回传

- 网页默认下载恢复原有多层分组表头：固定字段、动态字段和原表来源分组位于顶层，下层为子分组及具体字段名。保留原表共享单元格关系和原有列顺序，不将内部 `固定字段/商品名称` 等路径展平成一行标题。
- 标准化回传后按已确认字段保存文件中的列宽和表头行高，再次下载不会因清空值、删除说明行或缩短名称而重新收窄列。多行表头名称按字面保留，不把换行或斜杠改成新的布局层级。
- 可增删商品行和业务列、字段改名及调序。网页先逐列确认“对应已有字段 / 新增字段 / 忽略”，再确认商品身份及数据差异。新下载文件用隐藏定义名称提供稳定字段身份；旧文件按完整表头或唯一名称提供建议，最终以人工确认的对应关系为准，不按列位置硬套。
- 新增列选择普通字段、商品属性或商品规格，只修改当前任务，不写入全局字段配置。字段以独立 `header_path` 保存确认后的分层表头，字段名称里的斜杠不会误拆表头层级。新普通列沿用回传分组并独立导出；只有动态属性/规格在最终表生成时拼成 `字段：值`。
- 删除的列默认保留原字段及原值，也可明确移除本任务的可选字段和当前维护数据。必填、只读、唯一键及跨字段规则引用字段需要保留。缺列与清空单元格不同：存在的空白单元格会清空对应值。
- 隐藏的 `_workflow_record_id` 仍随每条商品保存。有效且唯一的 ID 对应原商品；无 ID 且内容/货号匹配、ID 重复或未知、疑似只排序业务列时，必须逐行选择已有商品、明确新增或忽略。整个 ID 列被删也可重新确认身份，不按当前行号自动恢复。新增商品由系统分配新 ID。
- 删除行先列入缺少明细，默认保留，只有勾选删除并确认保存才移除。按回传文件顺序保存商品，默认保留的缺少记录追加到末尾。结构、值、记录顺序、共享关系及修订在一个事务内保存，过期或并发修订拒绝覆盖；原始值及历史导出保留。
- 数据区可以新增或取消纵向合并，确认合并差异后按回传范围展开各条商品值，不把合并内空格当成清空。取消合并后的空白格则表示清空，需保留值时先填充。横跨多个业务字段的数据合并需先拆开，无法自动猜测各字段值。
- Excel/WPS 自身仍可能拒绝排序大小不同的数据合并区域。可只取消待排序数据区的合并、填充值后整行排序，保留表头合并；须把隐藏 ID 一起移动，不能只排序业务列。
- 保留表头行数和隐藏 `_workflow_meta` 任务信息工作表。标准化回传支持本文所述的图片和受支持计算公式；无法独立核验的公式仍需先在 Excel 中核对并粘贴为值。最终差异页显示改名、字段增删、归属、顺序及合并关系变化，结构变化须明确确认后保存。
- 已下载的 `table_v1` 单行 Table 文件继续支持读取和回传，避免丢失已经填写的修改。内部显式 `maintenance_file(..., table_mode=True)` 保留兼容能力，网页默认不再使用该格式。

## 多文件上传

- 支持一次多选或分次追加 `.xlsx` 文件，上传前可以逐个移除。每个任务最多 30 个文件，单个不超过 100 MiB、合计不超过 500 MiB；单个文件解压后最多 500 MiB。任务内最多 50 个有效工作表、20,000 条记录、200 万个源数据区域单元格，单表仍沿用既有解析限制。维护回传同样支持单个 100 MiB；部署代理请求体上限为 512 MiB，包含表单开销。
- 多个文件合并为一个任务，使用同一份字段快照，统一确认映射、维护、下载维护表、回传及导出标准商品表；不会按文件自动创建多个任务。
- 原文件独立保存。多文件任务的工作表标识带文件序号、工作表序号和名称，重名文件、重名工作表也不会串表；记录来源保存原文件名与原工作表名，合并单元格和保留列按各自来源处理。
- 任一文件格式或内容校验失败，整个任务失败，并提示具体文件；不导入部分成功的数据。单文件上传及历史任务保持兼容。

## 原表保留列

- 新标准化任务开启 `preserve_extras`，未匹配列按原工作簿的工作表顺序、列位置追加，值始终跟随原商品行。保留列上方按来源表分组，相邻“封窗”列合并为一个大类表头，“瓷砖”同样处理，下一行直接显示原列名；不显示“封窗 · I”等列字母或额外“原表保留列”层。仅合并大类表头，同名字段列和商品数据行分别保留。空表头以“未命名列 N”展示。网页维护、维护下载、回传校验和最终导出使用相同分组。
- 新任务使用 `source_header_layout=grouped` 和 `exclude_source_sequence=true`，明确名为“序号”或“行号”的原表列不参与自动匹配，也不追加到维护和导出表；商品编号、货号、型号等业务字段照常保留。网页维护表不显示额外的行序号栏。历史 `compact` 和 `provenance` 快照继续兼容，可按明确请求升级任务修订；升级后旧下载文件需重新下载后回传。
- 保留列只属于当前任务，不写入全局固定字段或动态字段配置。它们使用独立稳定 ID；网页回传支持增删列、改名和调序，通过上述结构确认流程处理。
- 保留列按文本原样传递，保留前导零、空值、空格、多行内容和长文本，不套用标准字段的类型转换或去空格。仅保留列有内容的备注行也保留；图片及计算公式先按下述规则解析为图片引用或已核验结果。
- 未映射列不会因旧客户端传入 `ignored_columns` 而丢弃；明确排除的整个工作表仍不导入。固定值规则不消耗原表列。一个来源映射到多个目标时，不重复追加该来源列。
- 重新确认字段时，从原表按新映射重建保留列；新匹配成功的列移入标准字段，新取消映射的列进入末尾。此操作仍会清空当前维护修改，页面会明确确认。
- 标准字段最多 200 个，任务内保留列另计；维护回传支持合并后超过 200 列的结构。完整维护区域仍受 200 万单元格限制，超限明确要求拆分，不截断、不丢列。
- 历史任务未开启该标记时继续使用原快照，不自动改结构。

## 配置与快照

- 新标准化任务使用 `source_retention_version=2`。右侧保留区按原工作表/数据区及原列顺序保存未匹配单元格；说明行占用已匹配列时，仅在说明行额外保留该列，避免说明文字进入商品名称、品牌、货号。原表空列仍为空，不补造价格或名称。
- 明确的合并说明、编号备注、重复表头、费用表和内部空行保留在原位置，并记录 `source.kind=context`；商品字段留空，不参与商品必填校验。真正缺少商品名称的商品仍阻断生成，并在网页与下载单元格批注中提示确认来源或补录。
- 保留区恢复来源表头层次、列宽、单元格字体、底色、对齐、行高及可投影的矩形合并。横向合并只允许来源字段，不能横跨商品业务字段或隐藏 ID；回传时展开同一逻辑来源单元格，再确认几何变化。拆分、排序、删列或修改值时不强行合并不同内容。
- 费用表不因页尾“备注”命中说明字段而把页尾当表头；纯分组表头下的第一条实际数据不再被误作第二层表头。按明确修复请求重新读取旧任务时，旧源数据文件、现有商品记录 ID、商品维护值及手工新增行保留；已人工删除记录的任务需要先核对恢复范围。

- 尺寸、照射面积使用文本，保留 `600*1200`、`2340*900*55/57/60`、`20-30m²` 等原文。明确的规格/标准尺寸、适用/试用面积表头结合本地值格式提供待确认映射，不向模型发送商品值；多个候选仍需人工选择。
- 质保/保修列额外完整保留原文。年、月、描述性期限，以及未注明单位的普通“质保时间”数字，不自动写入“质保天数”；只有明确按天表达的数据才自动匹配数字天数。
- 具有重复商品名称及业务表头、由整列空白分隔的左右独立表，分别作为数据区匹配。保留原文件、物理工作表、原始行号、区块起止列及图片来源；跨区块不混用名称、单位或价格。原文件无需拆开或改版。
- 进行中的字段确认任务可显式升级规格快照并重新读取源表；仅改变上述两个字段类型，保留字段 ID、名称、分组及布局设置。升级结果与新的源数据文件在同一修订中提交，旧源数据文件保留。已进入维护阶段的任务不允许直接升级，以免覆盖运营修改。

- 固定字段支持启停、名称、分组、顺序、类型、必填、可编辑、别名、说明、默认值、选项和数值范围。
- 固定字段 ID 在创建后保持不变，已发布字段通过停用代替删除。
- 配置存储于原 `workflow_objects`，类型 `fieldconfig`，按租户隔离，沿用现有管理员权限与乐观锁。
- 发布不覆盖进行中任务。任务保留配置版本、内容摘要、本地动态定义和完整 SOP 配置；导出按任务快照，不重新读取最新发布配置。
- 新建任务的字段快照标记 `matching_scope=all_fields`。旧任务不自动重建；处于字段确认阶段时可点击“重新分析全部字段”，仅用该任务自身快照升级匹配范围，不读取最新发布字段。已完成任务及原 SOP 的历史导出、回传保持原结构。
- 后续接口应通过适配层提供类目、字段稳定 ID、属性/规格分组、显示顺序、类型、必填和可选值；替换本地定义后继续使用相同的任务快照和 SOP 数据链路。

## 映射和数据边界

- 原表解析和“重新分析全部字段”将当前阶段、模型名称、真实批次完成数、各工作表状态和起止时间保存在任务的 `processing_progress` 中。页面每秒更新已用时，每 1.5 秒读取处理进度；刷新后沿用服务端开始时间，结束或失败后停止计时。批次进度只在真实结果返回时前进，缓存命中同样计为已处理；失败批次单独标识，不显示推测完成时间。进度检查不增加业务修订，过期执行或旧分析不能覆盖新修订的进度。
- 新标准化任务启用 `preserve_source_merges`。对直接来自单个源列的匹配字段，以及追加的原表保留列，记录原表数据区的纵向合并范围。网页维护、维护下载和最终导出按相同来源范围合并相邻且值一致的单元格；不因内容相同而合并独立来源。商品明细仍逐行保存，原表未合并的类别与价格各占一行。横向跨多个业务字段的单元格不在重排字段后强行合并。
- 没有来源列的平台字段（空值、默认值或常量）随原表共享行块合并。行块由原表数据区实际纵向合并范围的所有起止边界划分，支持不同列位置、两行或多行、嵌套及交错范围，不写死商品名称或类别。已有来源列仍严格遵循该列自己的合并关系；无纵向合并的原表不推断行块。不同历史维护值不强行合并。
- 共享单元格在线编辑一次，同一来源合并范围内的记录同步更新；分页、筛选只影响当前显示，不改变共享编辑范围。若历史记录已有不同值，按不同值分别维护，避免覆盖已有修改。标准化任务新回传流程确认差异后以文件中的纵向合并为准，允许增删或拆分共享范围；历史 SOP 严格回传继续要求原合并结构。
- 一个来源列允许填入多个不同目标字段，每个目标字段只保留一个明确取值规则。
- 模型仅接收字段元数据与表头，不发送商品行值；模型建议须由运营确认。置信度不足 85% 的结果仅提示人工选择，不自动建立绑定，原列进入保留区。响应中的未知 ID、非法列和重复目标被拒绝。
- 模型建议还会在本地检查来源列的实际数据类型。若整列非空值都不符合目标类型（例如复合规格 `600×600` 对数值型尺寸），提示人工确认并保留原列；不发送商品值给模型。包含可解析值的混合列继续使用原有维护校验，质保天数沿用统一的单位规范化规则。
- 首次语义分析把整份工作簿中所有需分析工作表的表头及未匹配目标合成一次模型请求，不按 25、50 或其他字段数量拆批。每个工作表使用独立字段标识和来源列标识，响应必须回到同一工作表；同名表头和相同原列号不会串表。每次上传和重新分析都独立调用模型，不复用其他任务或上次分析的确认映射，也不读取内存或 Redis 中的分析结果缓存。模型响应被截断或拒绝时明确报告失败，保留原数据和本地确定性匹配，不把不完整响应当作全部完成；临时故障沿用一次重试规则。整份读取仍遵循现有文件格式及容量校验，不静默截掉超过上限的数据。
- 模型生成响应允许等待 120 秒，连接超时为 10 秒；字段分析遇到超时、连接故障或临时服务错误时等待 1 秒后自动重试一次。认证、配置和响应格式错误不自动重试。成功批次仍保留，失败批次在 `model_errors` 中记录批次号和安全错误码，页面显示失败原因；服务日志记录尝试次数和耗时，不记录密钥、请求正文或上游错误正文。未匹配字段数量不等于模型调用失败。
- 直接复制、固定值、拼接、拆分、数值换算沿用 SOP 规则；不自动猜测售价、库存、保障政策或缺失商品数据。
- 新任务的所有目标字段均参与匹配；必填、类型规则适用于所有导入记录。无来源的必填字段需补录，无来源的可选字段保留空值或显式配置的默认值，不由模型编造。历史类目快照继续按原规则校验。
- 确认后的映射与来源工作表、行号一起存入记录，维护保留导入原值与当前值。
- 输出说明表不作为商品导入。供应商商品行中的 `DISPIMG` 单元格图片和普通嵌入图片会提取到当前任务的图片资源目录，用内容摘要去重；记录保存图片引用，原始图片字节不缩放或重编码。图片覆盖已有表头/数据时不覆盖原文字；包括标志等未放入商品单元格的原始图片也保留在完整导出包中。
- 维护表和最终表将商品图片嵌入对应单元格，保留图片比例，使用现有行高和列宽，不新增可见辅助列，也不改变分层表头；同图多处显示共用一个图片文件，避免反复写入导致回传文件膨胀。网页可查看缩略图和原图，图片访问沿用任务所属账号和租户权限。完整 ZIP 包含最终 Excel、生成说明和去重原始图片；导出批次有独立图片快照。
- 普通计算公式不交给任意代码执行，也不直接信任缓存。程序独立计算并核对缓存，支持有界本地单元格引用、加减乘除、整数幂、百分数，以及 `SUM/MIN/MAX/AVERAGE/COUNT/ROUND/ABS` 数值函数。共享公式按实际单元格展开；缓存缺失或过期时使用独立计算结果，页面列出原公式、缓存和采用结果。循环引用、除零、外部引用、未知函数或无法校验的结果明确报错，不能拿未核验缓存继续导出。
- 普通备注行沿用原识别逻辑，但新任务的未匹配列在备注行有内容时仍保留该行；需要由运营判断哪些记录属于商品。图片/公式兼容不会代替缺失名称、功率单位、质保年限等业务数据确认，也不会自动把年换算为天。
- 数值类型的固定字段 `warranty_days` 支持明确的“整数 + 天”，例如 `5840天`、`5840 天` 自动规范为数值 `5840`；导入、在线维护和回传共用此规则，原始值仍保留。年、月、区间或描述性文本不自动换算，其他数值字段不套用该规则。SKU 和带前导零编码按文本保留。

## API

- 标准化维护回传：`POST /workflow-tasks/{id}/maintenance/returns/inspect` 上传文件；`POST /workflow-tasks/{id}/maintenance/returns/{preview_id}/preview` 提交列和商品对应关系；原 `/returns/apply` 增加 `confirm_structure`。旧 `/returns` 严格预览接口兼容历史客户端。

- `GET /api/v1/field-profile`：读取租户草稿、发布配置与版本。
- `PUT /api/v1/field-profile`：保存草稿，要求 `base_revision` 和 `profile`。
- `POST /api/v1/field-profile/preview`：校验并预览字段输出结构。
- `POST /api/v1/field-profile/publish`：发布，要求 `base_revision`。
- `POST /api/v1/standardization-tasks`：上传一个或多个供应商 Excel；多文件使用重复的 multipart `excel_file` 字段，单文件仍用同名字段。支持幂等键，文件顺序、文件名或内容改变后不能复用原键。
- `POST /api/v1/workflow-tasks/{id}/mapping/analyze`：重新联合分析全部字段，只需 `base_revision`。旧客户端的 `categories` 参数仅为兼容接收，不再控制分析范围。
- 维护、校验、回传、导出沿用 `/workflow-tasks/{id}/...`。

# 多业务模板

左侧“模板管理”提供新建、复制、编辑、保存草稿和发布。原 `/field-profile` 配置以同一个记录 ID 保留为“通用商品模板”，不重写原发布字段或历史任务。新接口 `/field-profiles` 列出当前工作区模板；`POST` 创建空白模板或通过 `source_id` 复制指定模板的已保存草稿。每个模板独立保存草稿、发布版本和修订号，写入和发布需要管理员权限。

新建任务选择已发布模板，上传请求通过 `field_profile_id` 指定模板；不传时兼容原有通用模板流程。未发布或不存在的指定模板会直接报错，不会换成其他模板。任务保存模板 ID、名称、发布版本及完整字段快照。保存未发布草稿不影响新任务正在使用的发布版；之后发布也不会改变已有任务。模板复制不共享可变字段配置。

模板配置继续使用既有字段编辑器：启用、停用、类型、必填、别名、分组、顺序和动态字段。已发布固定字段 ID 不可删除，通过停用处理不再需要的字段。维护表仍使用分层合并表头和既有布局；固定字段、动态字段及右侧原表保留列的生成规则不变。维护表回传的结构调整只作用于该任务；最终导出仅将动态字段按商品属性和商品规格转换为“字段：值”。

回归测试：`tests/test_business_templates.py` 覆盖原配置兼容、模板及工作区隔离、发布冲突、历史快照不变、多文件上传、分层表头几何与样式、回传增删排序、最终动态字段汇总。`tools/verify_business_templates.cjs` 在隔离验收服务完成页面全流程，不能指向正式数据目录。
