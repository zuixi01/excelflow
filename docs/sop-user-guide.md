# ExcelFlow 商品整理工作流

## 日常操作

1. 在工作台新建任务，选择已发布的业务模板，上传原始 `.xlsx`。一个文件可以包含多个商品工作表。
2. 确认工作表、表头位置和字段对应关系。可配置取值、去空格、换算、拼接、拆分和固定值；未映射列默认作为扩展字段保留。
3. 在维护表修改数据，按需要筛选问题、排序、批量填充、增删记录。点击“保存并校验”产生新修订。货号等文本标识保留前导零。
4. 也可下载维护表，在 Excel 中编辑后回传。先查看差异，再确认保存。文件中缺失的记录默认保留，只有明确勾选才删除。请保留隐藏的记录标识及元数据；旧修订、重复或未知标识会被拒绝。
5. 处理完阻断问题后生成最终表。可以网页预览、逐文件下载或下载 ZIP。每个生成批次绑定当时的维护修订，后来修改数据不会改变历史文件。

任务及修订保存在服务端，刷新页面后可继续。未保存的网页编辑不会自动上传；离开页面前会提示保存。

内置模板使用原有 25 个商品字段，默认仅要求商品名称必填。正式业务需要的货号唯一性、必填性、枚举和跨字段规则，应在模板中心配置后发布新版本。

## 学习与发布模板

在模板中心上传 Excel，选择用途：导入样例、维护模板或最终输出模板。程序先读取工作表、表头和列宽，并将未识别字段作为扩展字段保留。上传输出模板时，第一份输出文件使用参考工作簿；其他输出文件由配置生成。

补充清楚的业务说明，再点击 AI 学习。AI 可以建议字段类型、必填项、别名和输出字段转换。结果仍是草稿，不会自动发布；不执行模型返回的代码或公式。业务唯一键、枚举、跨字段比较等也可人工配置，复杂配置放在高级 JSON 中。

样例试运行可用于在发布前检查字段校验和输出结果；上传样例后，AI 调整应使用新的原始样例，避免使用旧映射的数据。确认字段映射、业务规则和输出结构后即可发布；已发布版本不可编辑，可以创建新版本。试运行失败不会阻止发布，由配置人员决定是否继续发布。

导入规则、维护字段和所有输出方案组成一个不可变业务版本；已有任务继续使用创建时版本。输出支持多个文件、多个工作表、按字段分组、按分隔符展开 SKU，以及固定值、换算、拼接、拆分和显式公式。

## 模型设置

系统设置支持兼容 OpenAI Chat Completions 的 HTTPS 接口，可保存接口地址、密钥、模型名称并读取模型列表。本地已按本次配置选用 `gpt-5.6-luna`，已通过合成样例验证“学习规则 → 试运行 → 发布”。

默认只发送字段结构和用户业务说明，不发送样例记录。打开样例开关后最多发送三条截断样例，并排除标为敏感的字段。Windows 密钥使用当前系统账户的 DPAPI 加密保存；接口只返回是否已配置。更换接口地址会清除旧密钥，需重新填写。

## 当前支持范围

- 新流程仅支持普通 `.xlsx`：上传上限 20 MiB、200 列、20,000 条输入记录，工作簿最多 2,000,000 个单元格。每个输出工作表最多 20,000 条记录，单文件最多拆分 50 张表。
- 原表中的公式应先粘贴为值。输出模板允许受限制的本表公式；程序保留公式文本，计算结果由 Excel 完成，网页预览不计算公式。
- 图片、宏、外部连接、复杂绘图、输出数据区域合并和 Excel Table 等不受支持结构会提示处理；不承诺任意工作簿无损复刻。
- 参考表头未变时保留多行合并结构；调整标题或列顺序后按配置重建表头。复杂样式和公式依赖应在试运行文件中检查。
- 多文件使用同一维护快照独立生成，尚不提供通用跨文件关联计算、透视汇总或外部平台自动上架。
- 原有标准核验工具保留在侧栏入口。新流程不会自动调用平台目录服务。

## 运行与维护

本地前端默认 `http://127.0.0.1:5173/`，API 默认 `http://127.0.0.1:8000/`。沿用项目启动流程。未配置数据库时，新流程使用 `EXCEL_AUDITOR_DATA/workflow/workflow.sqlite3`（默认 `var/workflow/workflow.sqlite3`）。原文件、参考模板、快照、导出和模型配置也位于 workflow 目录，备份应包含数据库和文件。

配置 `DATABASE_URL` 时使用现有 SQLAlchemy 引擎，并需要先执行项目 Alembic 迁移到 `head`，新增版本为 `20260908_0005`。配置队列时使用现有 RQ；API 和 worker 必须共享同一 workflow 文件目录。本次未进行远程数据库迁移、生产部署或真实 Redis/PostgreSQL/S3 联调。

模板和模型设置写操作受 `EXCEL_AUDITOR_TEMPLATE_ADMINS` 限制，值为逗号分隔的用户 ID，默认 `local,service`；任务沿用现有租户隔离与 Bearer 鉴权。正式环境应使用已有鉴权配置，并明确管理员用户。

验证覆盖后端工作流、旧功能回归、数据库迁移、前端类型与构建，以及浏览器导入、编辑保存、刷新恢复、输出预览下载、模板试运行发布和移动布局。真实商家文件仍需按上述步骤检查其字段和业务规则；合成样例通过不能替代业务验收。
