# ExcelFlow 演示速记

## 一句话定位

将供应商格式不统一的 Excel，经字段映射、人工确认和规则校验，整理成可追溯的标准商品表。

## 六步主流程

发布字段配置 → 上传原表并冻结配置 → 识别表头与建议映射 → 人工确认 → 维护校验 → 冻结数据并导出。

## 三个概念

- 字段映射：品名这一列对应商品名称。
- 数据校验：销售价里的“待确认”不是有效小数。
- 标准值比对：货号 0001 的价格与平台标准记录是否一致；需要标准记录才能判断。

## 五句核心原理

1. 规则先做名称与别名匹配，AI 为剩余表头给出语义候选，人工确认后才执行转换。
2. 标准化字段映射只给 AI 表头与字段信息；0.85 是建议门槛，不是实测准确率。
3. 标准字段按类型校验，未匹配原列作为当前任务保留列；商品编码保留前导零。
4. 任务冻结字段配置，导出冻结当前数据；revision 防止旧页面覆盖新操作。
5. Excel 回传按记录 ID 对齐，并检查任务、版本和表结构，不能用普通文件随意覆盖。

## 四组组件

| 组件 | 作用 |
| --- | --- |
| Vue 前端 + FastAPI | 用户操作、接口、鉴权、业务入口 |
| Python + openpyxl | 主流程识别、转换、校验、维护和新表输出 |
| 数据库 + 文件目录 | 任务与逐行记录；原表与产物 |
| Redis/RQ + Worker | 可配置后台排队、处理与恢复 |

通用核验另有 Python 比对 → Manifest 修复计划 → .NET/OpenXML 路径，可配置 MinIO/S3。不要说当前所有导出都经过 .NET，也不要说所有 SOP 文件都存 MinIO。

## 三行小表怎么讲

货号“0001”保留前导零；“品名”根据别名对应商品名称；“含税价格”对应销售价；“用料”未配置为标准字段，保留在右侧。

第二条商品价格为“待确认”，校验阻断导出。演练假设运营确认价格为 99.00，明确修改后重新校验，再导出三条记录。99.00 是教学输入，不是模型推断或真实平台价格。

## 20 分钟顺序

前 4 分钟讲问题和架构；接着 5 分钟展示字段配置、上传与映射；再用 5 分钟展示错误、修改和维护；用 3 分钟解释回传与版本；最后 3 分钟导出并总结实现。

回传操作只能用当前网页任务刚下载的维护表。精简演练配置与实际网页配置可能不同，今晚必须用最终配置跑一次。

## 必须说准确的边界

- 当前主工作台是商品标准化；旧 SOP、平台核对和通用核验是其他链路。
- 当前标准化的外部运营平台尚未接入，动态字段来自本地模拟配置。
- 校验通过只代表满足当前规则，不等于商业内容一定正确。
- 主流程生成新的标准表，不承诺复制原文件全部宏、图片和公式。
- 最新实现合并工作簿各表的未匹配字段为一次模型请求，返回后做表作用域和本地类型检查；完整验证记录见讲义末尾。
- 最新重跑的五组针对性测试共 68 项全部通过；隔离三行演练通过，真实网页和外部模型仍需现场彩排。
