# ExcelFlow SOP 标准化工作流解决方案

方案日期：2026-09-08
文档状态：首版核心流程已在本地实现。本文保留设计目标；实际支持范围、运行说明及限制以 [SOP 使用说明](sop-user-guide.md) 为准。通用跨文件关联计算、透视汇总与生产环境联调未包含在本次本地实现中。

## 1. 目标与范围

将现有商品整理、标准核验和规则管理组织成完整业务流程：

**导入原表 → 生成标准维护数据 → 维护与校验 → 按输出方案生成最终表 → 下载归档。**

另设模板配置流程：

**上传 Excel 模板 → 程序解析结构 → AI 辅助生成规则草稿 → 人工确认 → 样例试运行 → 发布版本。**

日常用户选择业务流程并维护数据；模板管理员负责配置流程和发布模板。AI 负责辅助配置，已发布规则由后端确定性执行。

### 首版采用的产品假设

- 一个任务代表一批原始数据，首版上传一个 Excel 文件，可包含多个工作表。
- 维护表以系统保存的结构化数据为准，同时支持网页编辑和 Excel 下载后回传。
- 一个任务绑定一个业务流程版本，版本内包含导入规则、维护模板和输出方案。
- 一套最终表可包含多个工作表或多个 Excel 文件；每个输出文件有自己的模板版本。
- 首版导出并下载文件，不自动发布商品或写入外部平台。
- 第一条业务流程是“商家商品上架整理”。先用现有固定字段建立默认维护模板，随后允许增加模板字段。
- 首版模板学习与生成以普通 `.xlsx` 为明确支持范围。原有 `.xlsm` 能力保留在原流程；新流程识别到宏、控件、复杂绘图或不支持的结构时明确提示，不承诺自动无损转换。

这些假设可在业务样例评审时调整；实施前应固定首条流程的输入、维护和输出样例。

## 2. 用户操作 SOP

| 步骤 | 用户看到与操作的内容 | 后端行为 | 完成条件 |
| --- | --- | --- | --- |
| 1 导入原表 | 选择业务流程，上传文件，查看工作表预览 | 文件预检，识别表头，保存原文件及哈希，推荐字段映射 | 文件受支持，找到有效数据区域 |
| 2 确认字段 | 查看“原表字段 → 维护字段”；仅处理待确认项 | 应用别名、类型转换、单位换算及配置的补全规则；保留来源 | 关键字段映射明确，无未解决映射冲突 |
| 3 维护数据 | 修改单元格、批量填充、筛选异常，也可导出维护表 | 保存修订，执行字段及跨字段校验，显示错误和警告 | 当前修订的阻断性问题为零 |
| 4 生成最终表 | 查看输出文件清单、模板版本和数据范围，点击生成 | 固定数据快照，执行输出规则，渲染并回读校验 | 所有必需输出校验通过 |
| 5 下载归档 | 预览结果，逐个下载或下载整套文件 | 保存生成批次、版本关系、校验报告及产物哈希 | 生成批次完整可追溯 |

映射明确时自动进入维护步骤。维护数据初次校验合格时，直接显示“可生成最终表”，保留预览机会，不要求逐项重复确认。

业务阻断只针对当前流程要求：生成商品导入表必须有商品标识和名称，但可选备注缺失不应阻断。单次修改后的校验结果可能更新，但旧导出文件始终保留其原始版本关系。

## 3. 页面结构

### 3.1 工作台

主要入口为“新建任务”。列表展示任务名称、业务流程、当前步骤、待处理问题数、更新时间和继续操作按钮。

提供“待处理 / 维护中 / 可生成 / 已完成”筛选与按任务名、原文件名搜索。状态旁展示具体原因，如“3 个字段待确认”“12 条数据需补充”，避免只出现内部状态码。

### 3.2 任务详情

顶部始终显示业务步骤：导入原表 → 确认字段 → 维护数据 → 生成最终表。

- 导入页：文件选择、工作表识别结果、有效记录数和结构问题。
- 映射页：原始字段、示例值、目标字段、转换方式、确认状态。一个源字段映射多个目标字段时必须有明确拆分规则；多个源字段映射同一目标字段时必须有明确优先级或合并规则。
- 维护页：工具栏 + 数据表格 + 按需展开的问题面板。默认隐藏系统标识和追踪字段，支持查看原值和来源。
- 生成页：目标文件卡片、选用模板版本、记录范围、预览、生成进度与下载。

维护表格首版支持：分页、筛选、排序、单元格编辑、批量填充、枚举下拉、字段只读控制、问题定位、保存草稿和 Excel 回传。未知字段保留到扩展数据中；未输出的字段明确列示，不静默丢弃。

任务页面的主要按钮随步骤变化：“开始解析”“生成维护表”“校验并继续”“生成最终表”。下载报告、查看来源、技术详情放在次要位置。

### 3.3 模板中心

展示业务流程及其关联模板。模板详情提供“结构预览 / 字段与规则 / 样例试运行 / 版本记录”。

新增模板向导：选择模板用途 → 上传 Excel → 查看解析结果 → 补充业务说明 → AI 建议 → 确认规则 → 试运行 → 发布。

复杂 JSON 编辑放入高级设置。日常任务页面不要求填写 schema ID、API 路径或渲染参数。

### 3.4 系统设置

集中管理平台数据连接、AI 服务配置和技术参数。沿用现有鉴权能力，首版不因页面调整新增完整组织权限系统；后端仍需约束模板发布和任务修改的授权。

原“标准核验”保留为任务类型；其校验和差异能力也供 SOP 流程复用。

## 4. 三层模板与业务流程版本

### 4.1 导入规则 ImportProfile

定义输入工作表和数据区域的识别、表头别名、字段映射、合并与拆分、类型转换、单位转换、空值处理及重复记录策略。

匹配顺序建议为：用户明确选择 → 已发布精确规则 → 已确认别名 → 候选匹配。候选不满足确定性条件时进入确认页。常规任务不必每次调用 AI；遇到新结构时可显式使用 AI 辅助映射。

### 4.2 维护模板 MaintenanceSchema

定义稳定字段 ID、显示名称、类型、必填性、枚举、默认值、校验规则、业务唯一键、字段编辑权限和扩展字段策略。

系统记录 ID 与商品业务主键分开。系统记录 ID 用于维护和回传定位；SKU 等业务键用于业务校验，即使其尚未填写或被修改，也不会导致记录身份丢失。

现有商品 25 个字段作为默认模板内容，而非未来所有模板都必须遵循的硬编码字段集合。

### 4.3 输出模板 OutputTemplate

同时保存参考工作簿与可执行规则，定义：

- 文件和工作表命名、表头区域、数据起始行、列顺序与样式。
- 维护字段到目标字段的映射、固定值、缺省值、转换与计算。
- 按类目拆表、按配置展开 SKU、汇总及关联规则。
- 公式填充、数据验证以及明确支持的结构保留范围。
- 输出后的必填、唯一性、记录数、类型与工作簿结构校验。

扩展计算使用受限的规则操作集合。不得将 AI 生成的 Python、SQL 或任意表达式直接作为后端可执行代码。

### 4.4 输出方案 OutputPackage 与流程 WorkflowDefinition

输出方案引用一个或多个输出模板，声明必需文件、输出范围和文件间关联约束。业务流程将导入规则、维护模板和输出方案绑定为一个发布版本。

发布版本不可变。修改模板生成新草稿、新版本。任务创建时固定流程及各模板版本；已有任务升级时先预览字段迁移和规则变化，用户明确应用后生成新修订。

## 5. 维护数据、修订和回传

### 5.1 建议的数据对象

| 对象 | 作用及关键内容 |
| --- | --- |
| TemplateVersion | 模板类型、配置、参考文件、版本、内容哈希、试运行报告和发布状态 |
| WorkflowVersion | 固定导入规则、维护模板、输出方案版本及步骤配置 |
| WorkflowTask | 文件来源、流程版本、当前业务步骤和当前维护修订 |
| MaintenanceRevision | 数据修订号、父修订、编辑来源、创建人和校验状态 |
| MaintenanceRecord | 稳定记录 ID、类型化字段值、扩展字段及原始来源 |
| ValidationIssue | 所属修订、记录、字段、规则 ID、级别和可执行提示 |
| ExportRun | 固定的数据修订、模板版本、处理参数、执行状态与产物 |
| TemplateLearningRun | 输入材料、解析结果、AI 草稿、待确认项及样例结果 |

复用现有任务、审计、规则注册和产物存储能力，新增对象与现有任务通过关联 ID 连接。不要把维护状态塞入既有比较结果摘要中，也不直接放宽现有严格 RuleSet 来容纳所有新概念。

持久化实现适配当前可用环境；本地开发可使用受控本地存储，生产适配已有数据库体系。不能在每次编辑时把全部数据读入内存并重写整个 Excel。具体表结构、索引及迁移在实施阶段按现有仓储接口设计。

### 5.2 编辑一致性

每次保存携带基础修订号；基础版本过期时返回冲突信息，不能覆盖新修改。用户可先保存不完整草稿，生成最终表必须使用完成校验的数据快照。

正常化后的金额继续使用已有精确数值语义；标识、电话等文本保留前导零。网页显示值、持久化值与 Excel 回传解析必须遵守同一字段类型契约。

### 5.3 Excel 下载与回传

维护文件携带任务标识、模板版本、基础修订和记录 ID 等元数据。隐藏元数据用于定位，服务端仍需验证任务归属和修订有效性，不能把文件中的 ID 当作授权依据。

回传先展示新增、修改、缺失及冲突记录的差异预览，确认后生成新修订：

- 排序或改变行位置不改变记录身份。
- 新增行可分配新 ID；重复或未知 ID 进入冲突处理。
- 文件中缺少某行不直接解释为删除，先列为待确认删除候选。
- 非可编辑字段改动拒绝应用并明确说明。
- 元数据丢失、任务不匹配或版本过期时停止直接覆盖，提供重新匹配或解决冲突入口。

## 6. AI 模板学习

### 6.1 输入材料

最低输入为 Excel 模板及模板用途。空模板主要提供结构证据；若要推导输入到输出的转换，应提供一组原表、期望维护表、期望最终表和业务说明。

优先由解析器读取工作表、表头、合并区域、样式、公式和验证规则，再向 AI 提供必要的结构化信息与有限样例。AI 服务使用可替换适配器，具体供应商和调用配置在实施时确定，本方案不假设已接入模型服务。

### 6.2 学习输出

AI 输出受约束的配置草稿，每条建议包含目标字段、规则类型、参数、来源依据和待确认原因。区分“文件直接读取”“样例推断”“用户明确指定”。模型自报置信度不作为自动发布的充分条件。

无法推断的销售政策、必填条件、分类规则、外部编码和关联键进入待确认列表，不通过猜测补齐。

### 6.3 发布条件

草稿通过配置结构校验、字段引用校验、受支持操作校验及样例试运行。规则与期望结果不同的地方需展示到具体工作表、记录和字段。

管理员确认推断性业务规则后才能发布。试运行失败或核心规则未确认时，允许保存草稿，不进入已发布模板列表。

常规任务只调用已发布配置；AI 服务不可用不影响既有模板继续执行。新学习结果不会修改历史任务和发布版本。

### 6.4 学习反馈与边界

人工修正可保存为当前模板的新别名或规则草稿；跨商家、跨租户复用需要明确作用域。工作簿文字作为待分析资料，不作为系统指令执行。发往模型的业务样例按配置裁剪和脱敏，不默认上传整份工作簿。

## 7. 后端接入建议

建议新增独立 workflow 模块，包含编排、导入映射、维护修订、校验、输出和模板学习服务；通过适配器复用现有模块，避免把全部新增逻辑继续放入 api.py。

以下为拟议接口分组，不表示当前已存在：

| 接口组 | 主要职责 |
| --- | --- |
| `/api/v1/workflow-definitions` | 列出和读取可用业务流程及版本 |
| `/api/v1/workflow-tasks` | 创建任务、查询列表与步骤、导入文件 |
| `/api/v1/workflow-tasks/{id}/mapping` | 查看、确认导入映射，创建维护修订 |
| `/api/v1/workflow-tasks/{id}/maintenance` | 分页读取数据、保存编辑、校验、下载与回传 |
| `/api/v1/workflow-tasks/{id}/exports` | 创建生成批次、读取状态和下载文件 |
| `/api/v1/templates` | 模板草稿、版本、测试与发布 |
| `/api/v1/template-learning-runs` | 模板解析、AI 草稿、状态与确认项 |

同步请求处理轻量编辑和读取。文件解析、模板学习及批量生成使用已有后台任务机制；有 Redis/RQ 时走队列，本地使用明确的开发执行方式。

业务步骤与执行状态分开保存：业务步骤为导入、映射、维护、输出、完成；执行状态为等待、运行、成功、失败、取消。失败时保留最近有效修订，允许从失败步骤重试。

生成任务使用幂等标识避免重复提交。整套输出中必需文件失败时，整个生成批次显示失败；已生成文件可用于诊断，但不能标示为完整交付包。取消和失败需清理本次临时产物，保留原文件、有效维护修订和历史成功产物。

## 8. 现有能力复用与调整

| 当前模块或能力 | 处理建议 |
| --- | --- |
| 商家工作表发现、固定字段映射与提取 | 保留为首个导入适配器，逐步将字段定义配置化 |
| 类型规范化、字段和跨字段校验 | 作为维护校验与导出校验的公共引擎 |
| 商品类目解析、SKU 展开 | 作为可选输出操作，按模板启用 |
| Open XML 渲染器与既有安全校验 | 在已支持结构范围内复用；新输出操作需补充能力校验 |
| 规则草稿、发布版本、内容哈希 | 复用版本机制，新模板配置保持独立明确的契约 |
| 人工映射确认与商品修订 | 复用交互和审计模式，新增通用单元格编辑与回传流程 |
| 任务、鉴权、租户隔离、产物存储 | 复用基础能力，增加流程与修订关联 |
| 当前 App.vue 三个功能页 | 拆分任务列表、步骤页面、维护表格及模板中心组件 |

旧接口先保留。新流程端到端验收通过后，再把默认商品入口切换到 SOP，避免新页面上线后仅有导入、没有维护与最终输出闭环。

## 9. 分阶段实施与验收门槛

### 阶段 0：固定一条真实业务流程

确认原表样例、维护字段、业务唯一键、必填规则、输出文件清单，以及期望结果。以现有商品字段作为初稿，不推定它就是最终业务标准。

交付：三类样例与规则清单，形成第一条流程的验收夹具。建议至少覆盖正常、多工作表差异、缺字段/异常值三种输入。

### 阶段 1：实现完整 SOP 核心

实现任务列表与步骤页、默认导入配置、持久化维护数据、网页编辑、校验和按一个固定输出方案生成最终表。

验收：真实样例可完成导入、修改、保存、刷新恢复、校验和下载；来源可追溯，关键问题可阻断，重复生成不串用其他修订。此阶段先验证主闭环，不以页面原型代替完成。

### 阶段 2：模板化及 Excel 维护回传

将固定流程配置迁移到版本化模板，支持输出方案中的多个文件；完成维护表下载、回传差异预览与冲突处理。

验收：同一维护修订能按两个已配置输出方案生成正确结果；模板升级不改变旧任务；维护表排序回传仍正确匹配，缺行不静默删除。

### 阶段 3：AI 辅助模板配置

实现 Excel 结构解析、AI 适配、配置草稿、待确认项、试运行及发布流程。

验收：对约定模板样例，系统能生成可检查草稿；错误推断被试运行或人工确认拦截；未发布草稿不能用于正常生产任务；AI 不可用时已发布流程仍可运行。

### 阶段 4：业务扩展与容量验证

依据实际需要加入真实平台连接、更多输出场景及性能优化。容量门槛按首条流程的真实行列数、并发任务、图片和公式情况确定，不套用历史通用核验性能指标。

## 10. 关键验收用例

1. 导入多个工作表后，记录数与约定过滤规则一致，每条维护记录可追溯来源。
2. 同义表头正确映射；歧义、重复目标映射需要明确处理，不能后列覆盖前列。
3. 金额精度、文本前导零、日期和枚举在网页保存与 Excel 往返后保持约定语义。
4. 修改、刷新、退出再进入后数据仍在；陈旧基础修订不能覆盖最新修改。
5. 必填错误阻断生成；警告按流程约定允许继续；修复后更新校验结果。
6. 回传排序、增行、缺行、重复 ID、未知 ID 和过期修订均得到明确结果。
7. 输出文件名、表名、列顺序、必填字段、公式和关联记录符合期望样例。
8. 同一数据快照、模板版本及参数产生语义一致的结果；不要求含时间戳和压缩元数据的 Excel 文件字节完全一致。
9. AI 草稿中的未知操作、错误字段引用和无依据业务规则不能绕过校验发布。
10. 失败或取消不会破坏输入和有效修订；用户只能访问授权范围内的任务、模板和产物。
11. 不支持的工作簿结构在明确步骤提示，不静默丢失后仍宣称生成成功。
12. 已有标准核验、规则版本和文件下载的相关回归检查通过。

## 11. 首版明确不做

不构建通用可视化流程编排器、不训练专属模型、不宣称支持任意 Excel 无损学习、不引入多人实时协同、不自动执行 AI 生成代码、不在没有接口契约时写回真实平台。

优先交付稳定可用的商品 SOP、可持久维护的数据和可验证的模板规则。AI 的价值通过模板配置结果的正确性与可审阅性验收，不预先承诺节省比例或识别准确率。

## 12. 实施前需由业务样例确定的事项

- 维护字段及可编辑范围：沿用哪些默认商品字段，哪些必须新增或保留为扩展。
- 最终表的实际接收方、文件数量、目标模板及字段编码约束。
- 商品与 SKU 的主键、重复记录策略、补全优先级、价格和规格转换规则。
- 图片、公式、宏等内容的实际使用情况和必须保留的范围。
- 代表性数据规模及可接受处理时间。

以上是需求取证项，不影响当前方案结构；实际开发验收必须基于业务方认可的期望结果，不能用通用示例代替真实规则。
