# 2026-11-04 生产发布候选检查

目标环境：公司内部约 50 人，Ubuntu 24.04 x86-64，8 核 16 GiB。当前为本地发布候选，尚未部署到目标服务器。

## 本地完成

- 生产 Compose 新增 HTTPS 入口；Web 的 8080 只绑定主机回环地址。入口覆盖客户端伪造的来源和协议头，API 只信任私有代理链。
- 模型和平台字段密钥使用只读文件挂载，非 root API/Worker 通过专用组读取；预检校验权限、证书有效期、证书域名、密钥格式、服务地址与占位值。
- `deploy/production.sh` 只接受干净且带 `vX.Y.Z` 标签的提交，按提交 SHA 拉取发布流水线镜像，不在生产服务器现场构建应用。
- 移除镜像构建中的 Alpine 全量升级；发布流水线补充生产 Compose 和 TLS 代理校验。
- 主工作流因重新分析的新鲜度要求关闭跨任务 AI 缓存，文档已按实际行为修正容量说明。

## 本地验证

- Python 全量回归退出码 0；部署预检、启动安全及新鲜字段分析专项测试通过。
- `pnpm --dir apps/web build` 通过；生产 Compose 与 TLS 叠加配置解析通过。
- Linux API 和 Web 镜像均构建成功；Linux ExcelRenderer 导出烟测通过。
- 实际 Web 镜像经 HTTPS 代理转发到 API：`X-Forwarded-Proto=https`，Host 正确，伪造的客户端来源头被覆盖。
- 在 Linux 容器中验证非 root 用户通过补充组读取 `640` 的模型密钥文件。
- 本机 Docker Scout 未登录，无法完成本地漏洞扫描；发布工作流仍以 Anchore 高危扫描为阻断门禁。
