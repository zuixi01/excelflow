# 生产改造交付与验收记录

日期：2026-11-03。目标：公司内部约 50 人、8 核 16 GB。用户已确认尚未准备生产服务器。本轮完成代码与本地隔离验证，不代表生产上线或实机容量验收通过。

## 已完成

- 多文件上传分块落盘，保留单个 100 MiB、合计 500 MiB、30 文件限制。multipart 解析前获取共享上传名额，检查请求体和磁盘余量；生产临时文件落到受监控的数据磁盘。普通 JSON 请求有独立大小限制。
- 主工作流共享准入和执行限制：全站 2 个执行、50 个等待，每人 1 个执行、3 个等待。数据库事务串行化计数，多个 API/Worker 共用限制；资源忙不消耗任务重试次数。
- 维护表生成、回传识别/差异预览、名称确认、维护保存、字段确认/分析、导出快照准备通过持久后台任务执行。复用执行租约、故障恢复、版本冲突和过期执行隔离。最终导出继续使用独立队列。
- 前端支持 202 / Location 查询结果，显示处理状态，刷新后可从处理记录继续下载或读取预览。
- 模型并发通过共享资源租约控制；Linux 生产配置只保存密钥引用，密钥由外部只读文件提供；HTTP 模型仍不允许用于生产。
- 大任务排序只读取记录 ID 与排序键，再加载当页完整记录；保留原数值/文本排序规则。此项减少宽记录内存，并未声称所有排序已经变为数据库索引排序。
- 生产 Compose 默认 2 个 API 进程、1 个导入 Worker、1 个导出/维护 Worker、恢复服务；配置容器资源上限、真实 Worker 心跳检查和启动依赖。旧队列按 legacy profile 显式启用。
- 提供管理员运行状态、共享队列指标、保守清理工具、停写备份/校验/空目标恢复工具及部署手册。
